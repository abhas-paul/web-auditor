## 📖 Overview

**Web Auditor** is a full-stack web application that lets authenticated users audit any public website and receive a comprehensive, AI-generated report. Under the hood it combines Google Lighthouse (performance & accessibility), Cheerio-based HTML parsing (SEO & links), HTTP header inspection (security), and robots/sitemap checks (crawlability) — then pipes all raw data into Google Gemini 2.5 Flash to produce a structured, human-readable report with executive summary, prioritized action plan, revenue-impact analysis, and more.

Reports are persisted per-user in MongoDB and can be exported as print-ready PDF files.

**⚡ Request flow for report generation:**

1. Authenticated user submits a URL from the dashboard.
2. Backend runs 5 audits **in parallel**: Lighthouse, SEO, Security, Crawlability, Link analysis.
3. Raw audit data is sent to Gemini 2.5 Flash, which returns a structured JSON report validated with Zod.
4. Report is saved to MongoDB and the `reportId` is returned to the frontend.
5. User is redirected to the report detail page.
6. Optionally, user can export the report as a PDF — the backend uses Puppeteer to render the report page and convert it.

## ✨ Features

- 🔐 **User authentication** — register, login, logout with HTTP-only JWT cookies
- 🛡️ **Protected routes** — both frontend guards and backend middleware
- ⚡ **Parallel website auditing**:
  - 🚀 Performance — Lighthouse scores (LCP, CLS, INP, FCP, Speed Index, TBT)
  - 🔍 SEO — title, meta description, H1 count, canonical URL
  - 🔒 Security — CSP, HSTS, X-Frame-Options, X-Content-Type-Options headers
  - 🕷️ Crawlability — `robots.txt` and `sitemap.xml` presence
  - 🔗 Links — internal vs. external link counts
- 🤖 **AI-structured report** (via Google Gemini 2.5 Flash) with 9 sections:
  - 📊 Executive Summary
  - 🚀 Performance Audit
  - 🔍 SEO Audit
  - 🔒 Security Audit
  - ♿ Accessibility Audit
  - 🎨 UX/UI Review
  - 📈 Competitor Benchmark
  - 💰 Revenue Impact Analysis
  - 📋 Prioritized Action Plan
- 🗂️ **Report history** — all past audits stored per-user, newest first
- 📄 **PDF export** — Puppeteer renders the authenticated report page and streams a print-ready A4 PDF

## 🔌 API Reference

> **Base URL:** `http://localhost:3000`
> Authentication uses an HTTP-only cookie (`token`) set automatically on login/register.

### 🔐 Auth — `/auth`

| Method | Endpoint | Auth Required | Description |
|--------|----------|:---:|-------------|
| `POST` | `/auth/register` | No | Create a new account |
| `POST` | `/auth/login` | No | Login and receive auth cookie |
| `POST` | `/auth/logout` | No | Clear auth cookie |
| `GET` | `/auth/me` | No | Return current user from cookie |

#### `POST /auth/register`

**Request body:**
```json
{
  "name": "Abhas Paul",
  "email": "abhas@example.com",
  "password": "yourpassword"
}
```

**Response `201`:**
```json
{
  "success": true,
  "message": "User registered successfully",
  "user": { "id": "...", "name": "Abhas Paul", "email": "abhas@example.com" }
}
```

---

#### `POST /auth/login`

**Request body:**
```json
{
  "email": "abhas@example.com",
  "password": "yourpassword"
}
```

**Response `200`:**
```json
{
  "success": true,
  "message": "Logged in successfully",
  "user": { "id": "...", "name": "Abhas Paul", "email": "abhas@example.com" }
}
```

---

#### `GET /auth/me`

**Response `200`:**
```json
{
  "authenticated": true,
  "user": { "id": "...", "name": "Abhas Paul", "email": "abhas@example.com" }
}
```

### 📊 Reports — `/reports` *(all routes require authentication)*

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/reports/generate-report` | Run a full audit for a URL |
| `GET` | `/reports/` | Get all reports for the current user |
| `GET` | `/reports/:reportId` | Get a single report by ID |
| `GET` | `/reports/:reportId/pdf` | Download the report as a PDF file |

#### `POST /reports/generate-report`

**Request body:**
```json
{
  "url": "https://example.com"
}
```

**Response `200`:**
```json
{
  "success": true,
  "reportId": "6859e1a2f4c3b20012345678"
}
```

> **Note:** This endpoint runs Lighthouse (requires a Chromium browser) and Gemini AI inference. Expect **30–90 seconds** response time depending on network and machine speed.

---

#### `GET /reports/`

**Response `200`:**
```json
{
  "success": true,
  "count": 3,
  "reports": [
    { "_id": "...", "url": "https://example.com", "createdAt": "..." }
  ]
}
```

---

    "url": "https://example.com",

      "executiveSummary": {},
      "performanceAudit": {},

      "accessibilityAudit": {},
      "uxUiReview": {},
      "competitorBenchmark": {},
      "revenueImpactAnalysis": {},
      "prioritizedActionPlan": {}

    "createdAt": "..."

---

#### `GET /reports/:reportId/pdf`

Returns a binary `application/pdf` stream.

**Response headers:**
```
Content-Type: application/pdf
Content-Disposition: attachment; filename="audit-report-<id>.pdf"
```

## 🛠️ Installation Guide

### 📦 Prerequisites

| Requirement | Version |
|---|---|
| [Bun](https://bun.sh/) | >= 1.0 |
| [Node.js](https://nodejs.org/) | >= 18 (for Next.js) |
| MongoDB | Atlas cluster or local instance |
| Chromium-based browser | Brave, Chrome, or Chromium |
| Google Gemini API key | [Get one here](https://aistudio.google.com/app/apikey) |

---

### 1. 📥 Clone the repository

```bash
git clone https://github.com/abhas-paul/web-auditor.git
cd web-auditor
```

### 2. 🖧 Install backend dependencies

```bash
cd backend
bun install
```

### 3. 🖥️ Install frontend dependencies

```bash
cd ../frontend
bun install
# or: npm install
```

---

## ▶️ Running the Project

### 🖧 Backend

```bash
cd backend
bun run dev       # development with hot-reload (--watch)
# or
bun run start     # production
```

The API server starts on **http://localhost:3000**.

---

### 🖥️ Frontend

```bash
cd frontend
bun run dev
# or
npm run dev
```

> The default Next.js port is `3000`, but the backend occupies that port. Configure the frontend to run on `3001` by updating your `package.json` dev script:
> ```json
> "dev": "next dev --port 3001"
> ```

The frontend will be available at **http://localhost:3001**.

## 🌍 Environment Variables

### 🖧 Backend — `backend/.env`

```env
# MongoDB connection string
MONGO_URI=mongodb+srv://<user>:<password>@cluster0.example.mongodb.net/auditor_db

# JWT secret (use a long, random hex string)
JWT_SECRET=your_jwt_secret_here

# Google Gemini API key
GEMINI_API_KEY=your_gemini_api_key_here

# Frontend origin for CORS and PDF rendering
FRONTEND_URL=http://localhost:3001

# Absolute path to your Chromium/Brave/Chrome executable (for Puppeteer PDF)
BROWSER_PATH=C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe
```

> **Important:** The Lighthouse service also has a hardcoded `chromePath` inside `backend/src/services/lighthouse.service.ts`. Update that value to match your local browser installation if it differs.

---

### 🖥️ Frontend — `frontend/.env.local`

```env
# URL of the backend API (trailing slash required)
NEXT_PUBLIC_API_URL=http://localhost:3000/
```

## 🚧 Known Issues

- 🌐 **Hardcoded Lighthouse browser path** — `backend/src/services/lighthouse.service.ts` has the Chrome/Brave path hardcoded. Update it to match your local Chromium installation.

- ⏳ **Slow report generation** — Lighthouse + Gemini AI can take 30–90 seconds. There is currently no real-time progress indicator on the frontend during this period.

- 🖨️ **PDF requires both servers running** — Puppeteer navigates to the live frontend to render the PDF. Both the backend and frontend must be running when a PDF is requested.

- 📧 **No email verification** — User registration does not include email confirmation or account validation.
